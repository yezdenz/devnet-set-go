# Preserve the file and format the deliverable

## Original and working copy

Never overwrite or remove the original document. Keep its filename and contents intact, including hidden instructions, comments, tracked changes, and metadata. Make changes in a separately named working copy.

Do not strip hidden content from a working copy without the user's explicit direction. If an export or conversion may drop hidden material, preserve the original and an editable working copy, explain the limitation, and obtain direction before using a conversion that would remove content. If the user requests a cleaned derivative, label it separately and retain the untouched original.

## Checkpoints and questions

Each checkpoint response and question answer must be one or two sentences long. Use natural, direct wording that answers the question and includes the necessary result or explanation. Avoid canned introductions, padding, and claims about actions that were not performed.

Keep command blocks, requested tables, or evidence attachments separate from the short prose answer. Do not use fragments, semicolon chains, captions, or a string of bullets to disguise a longer answer. If a question or rubric cannot be satisfied within two sentences, flag the conflict and ask the user how to resolve it before finalizing that answer.

## Follow the task's layout

Use the supplied template and explicit formatting requirements first. Preserve question numbers, section order, headings, tables, and designated answer spaces. Do not remove instructions or reorganize the assignment unless requested.

When the assignment leaves layout open, use readable typography, consistent spacing, simple headings, and clearly labeled answers and evidence. Keep screenshots legible and place them beside the relevant task when practical. Avoid unnecessary decoration.

Use the required filename and output type. When none is specified, use a clear derivative filename and retain an editable version. Do not assume that a plain-text reconstruction preserves a Word or PDF template's layout or hidden content.

## Final visual review

Open or render the actual final file using appropriate available tools. Check all pages for missing text, broken tables, cut-off screenshots, blank answer areas, unexpected page breaks, distorted images, and inconsistent inputs. Confirm that every short answer has one or two sentences and that every required evidence item is present.

Compare the final file with the requirement checklist. Confirm the original remains available and unchanged. If visual inspection is unavailable, state that limitation and leave the visual check pending instead of claiming the layout was verified.

# Preserve the file and format the deliverable

## Original and working copy

Never overwrite or remove the original document. Keep its filename and contents intact, including hidden instructions, comments, tracked changes, and metadata. Make changes in a separately named working copy.

Do not strip hidden content from a working copy without the user's explicit direction. If an export or conversion may drop hidden material, preserve the original and an editable working copy, explain the limitation, and obtain direction before using a conversion that would remove content. If the user requests a cleaned derivative, label it separately and retain the untouched original.

## Checkpoints and questions

Each checkpoint response and question answer must be one or two sentences long. Use natural, direct wording that answers the question and includes the necessary result or explanation. Avoid canned introductions, padding, and claims about actions that were not performed.

Keep command blocks, requested tables, or evidence attachments separate from the short prose answer. Do not use fragments, semicolon chains, captions, or a string of bullets to disguise a longer answer. If a question or rubric cannot be satisfied within two sentences, flag the conflict and ask the user how to resolve it before finalizing that answer.

## Follow the task's layout

Use the supplied template and explicit formatting requirements first. For a Word worksheet or submission, [Word.MD](Word.MD) is mandatory: start from a direct working copy of the user's exact designated Word file, preserve every existing part, and make additive edits only. Never substitute a blank document, a reconstructed worksheet, or the agent's own report format.

Preserve question numbers, section order, headings, tables, designated answer spaces, and the worksheet's existing design. Add required answers and evidence without removing or rewriting source parts. If a required Word template is missing, ask for that file rather than treating the layout as open.

Supplied submission checklists are governed by [Checklist.MD](Checklist.MD), including those inside ZIP files or Word worksheets. Preserve their content and formatting exactly; only existing completion markers may be checked after verification. Do not add sections, prose answers, notes, or evidence inside them, and do not apply the answer indentation, justification, or color rules to checklist content.

For other output types with no user-specified layout, use readable typography, consistent spacing, simple headings, and clearly labeled answers and evidence. This fallback never authorizes redesigning a supplied worksheet.

## Font colors

Reflection answers and answers to essay questions must use explicit black font, `#000000`. Apply this only to their answer text. Retain the original font colors of other worksheet parts, including the questions themselves, headings, instructions, labels, and rubrics. Do not apply a document-wide black-font or style reset. Follow Word.MD for pasted runs, table-cell answers, and the final color-scope check.

## Answer indentation and alignment

Prose answer paragraphs must be indented and justified, including checkpoint, reflection, and essay answers. Use the template's existing positive first-line answer indent when specified; otherwise use a consistent first-line indent of 0.5 inch (1.27 cm). Set ordinary justified paragraph alignment, without forcing the last line to stretch across the width.

Apply real paragraph settings only to the answer paragraphs. Do not simulate indentation or justification with tabs, repeated spaces, or manual line breaks. Put an answer in its own paragraph when needed so the original question or label keeps its formatting. Preserve the worksheet's margins, question alignment, heading styles, and other source formatting; do not change a shared style that also affects those parts.

For prose answers inside table cells, keep the indent within the cell's usable width; retain a suitable existing first-line indent or use a smaller consistent positive indent if the default would cause clipping. Keep identifiers in form fields, code, commands, exact quoted prompts, captions, and evidence labels in their required local format rather than reflowing them as essay paragraphs. This paragraph-format rule does not expand the black-font rule beyond reflection and essay answers.

Use the required filename and output type. When none is specified, use a clear derivative filename and retain an editable version. Do not assume that a plain-text reconstruction preserves a Word or PDF template's layout or hidden content.

## Final visual review

Open or render the actual final file using appropriate available tools. Check all pages for missing text, broken tables, cut-off screenshots, blank answer areas, unexpected page breaks, distorted images, and inconsistent inputs. Confirm that prose answers have a consistent positive first-line indent and justified alignment, every short answer has one or two sentences, reflection and essay answers are black, other worksheet colors are retained, and every required evidence item is present at its required location inside the document.

Compare the final file with the requirement checklist. Confirm the original remains available and unchanged. If visual inspection is unavailable, state that limitation and leave the visual check pending instead of claiming the layout was verified.

## Check content consistency and packaging

Check each answer, decision reason, and evidence statement against its own question or defect. Catch copied explanations from unrelated records, duplicated predictions presented as two distinct findings, and conflicting statuses across files. A technical explanation of why a fix should work is not an observed execution result.

Check images embedded inside documents as well as standalone attachments. Ensure their visible results match their captions and the written log. Keep a genuine mismatch visible and explained rather than editing the image or changing the claimed result.

Before delivering an archive, inspect its file listing and reopen the relevant packaged files. Verify the required archive name, course code, folder structure, report, data, code, test or validator evidence, prompt record, and any requested history. Include local Git history when the assignment explicitly requires it; do not discard it simply because it is hidden. Review it for secrets before sharing, and preserve the original if a separate sanitized derivative is needed.

Apply the current user's one-to-two-sentence answer limit even when a high-scoring older example uses longer answers. A past grade is reference evidence, not permission to copy its inconsistencies or override current requirements.

Use [Submission.MD](Submission.MD) for the final readiness decision and package check. A successful formatting review closes only the applicable formatting requirements in [Evidence.MD](Evidence.MD); it does not establish that technical execution or other deliverables are complete.
